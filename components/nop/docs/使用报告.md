# NOP SDK 使用报告

> 面向固件/厂家集成方：如何编译、链接、对接 HAL、收发 NOP 命令。
> 当前版本 0.1.0（N0），在 x86_64 Linux（gcc 13.3 / CMake 3.28）验证通过。

## 1. 编译

### 1.1 本机（host）

```sh
cd nop_sdk
./build.sh                 # 配置 + 编译 + 跑 ctest
```

或直接用 CMake：

```sh
cmake -S . -B build -DCMAKE_BUILD_TYPE=RelWithDebInfo
cmake --build build -j
(cd build && ctest --output-on-failure)
```

### 1.2 交叉编译（按不同工具链，和 TUTK 一样跨平台）

```sh
# Fullhan arm-uClibc（FH8852/FH8856）
./build.sh arm
#   等价：-DCMAKE_TOOLCHAIN_FILE=cmake/toolchain-arm-fullhanv2-uclibc.cmake
#        -DTOOLCHAIN_ROOT=/opt/arm-fullhanv2-linux-uclibcgnueabi
#        -DNOP_OSAL_PORT=linux_uclibc

# Windows x64（MinGW-w64）
./build.sh windows
```

新增 SoC 只需复制 `cmake/` 下一个 toolchain 文件改编译器前缀即可——库本身除
libc（POSIX 另需 pthread）外**无外部链接依赖**。

### 1.3 安装产物（TUTK 式 include + lib 布局）

```sh
cmake --install build --prefix /your/staging
# 生成：
#   /your/staging/include/nop_sdk/...      公共头
#   /your/staging/lib/libnopcore.a         静态库
#   /your/staging/lib/libnopcore.so.0.1.0  动态库
```

## 2. 集成三步

```c
#include "nop_sdk/nop_sdk.h"

/* 第 1 步：注册硬件 HAL（或开发期用打印桩 hal_stub_register_all()） */
static const hal_system_if my_system = {
    my_get_device_info, my_reboot, my_factory_reset, &my_ctx
};
hal_register(HAL_SYSTEM, &my_system);
hal_register(HAL_VIDEO,  &my_video);   /* 注册谁 → 谁的能力被点亮 */

/* 第 2 步：创建 app（能力随已注册 HAL 自动点亮） */
nop_app_config_t config = { 0 };
config.role = NOP_ROLE_IPC;
config.auto_caps = 1;
nop_app_t *app = nop_app_create(&config);

/* 第 3 步：把任意传输收到的请求信封喂进来，拿到响应信封 */
char *response = NULL;
nop_app_dispatch(app, "{\"func\":\"getDeviceInfo\",\"args\":{}}", &response);
/* ... 通过你的传输回写 response ... */
nop_app_free_response(response);

nop_app_destroy(app);
```

链接：`-lnopcore -lpthread`（POSIX）。

## 3. 公共 API 速查

| 函数 | 作用 |
|---|---|
| `nop_sdk_version()` | SDK 版本串 |
| `nop_app_create(config)` | 装配能力集+路由+全部内置 handler |
| `nop_app_dispatch(app, json_in, &json_out)` | 分发一条请求信封→响应信封 |
| `nop_app_free_response(json_out)` | 释放响应串 |
| `nop_app_set_capability(app, cap_id, enable)` | 运行期开关某能力（如 `CAP_LIGHT`） |
| `nop_app_destroy(app)` | 释放 |
| `hal_register(id, vtable)` | 注册硬件接口表 |

请求/响应信封格式：

```jsonc
// 请求
{ "func": "命令名", "args": { ... } }
// 响应（return 字段在响应时才包进 content；业务错误走 content.error）
{ "statusCode": 200, "statusMsg": "OK", "content": { ... } }
// 状态码：200 成功 / 400 参数错 / 501 未实现（命令未注册 或 能力未点亮）
```

## 4. 能力门控行为

- 命令未注册 → `501`。
- 命令所属能力未点亮 → `501`。
- 对应 HAL 未注册 → 该命令 `501`（不崩、无需写桩）。
- `auto_caps=1` 时，注册 `HAL_VIDEO/PTZ/LIGHT` 即点亮 `CAP_STREAM/PTZ/LIGHT`。
- `CAP_DEVICE/AUTH/SYSTEM` 为纯协议能力，恒为开。

## 8. ONVIF 客户端（可选，`NOP_WITH_ONVIF=ON`）

内置 ONVIF 客户端（vendored Happytimesoft 库，原文件零改动 + 一层 C 适配）。

```sh
cmake -S . -B build-onvif -DNOP_WITH_ONVIF=ON
cmake --build build-onvif -j
./build-onvif/examples/onvif_client_demo 5 admin admin   # 发现5秒，账号 admin/admin
```

完整客户端能力（共 42 个 `nop_sdk/nop_onvif.h` 纯 C 接口）：运行时、发现/监听、
设备句柄(连接/鉴权)、设备服务(信息/能力/时间/重启/复位)、媒体(profiles/流地址/
快照URI/抓图/视频源)、PTZ(连续·相对·绝对移动/停止/预置位/Home)、成像(读写亮度
对比度饱和度锐度)、事件(拉点订阅)、固件/备份/恢复。

```c
#include "nop_sdk/nop_onvif.h"

nop_onvif_global_init();
nop_onvif_discover(NULL, 5, on_device_found, &ctx);              /* LAN 发现 */

/* 针对某台设备：建句柄 → 鉴权 → 查询/控制 */
nop_onvif_device_t *dev = nop_onvif_device_create(host, port, "/onvif/device_service", 0);
nop_onvif_device_set_auth(dev, "admin", "admin");

nop_onvif_device_information_t info;
nop_onvif_get_device_information(dev, &info);                    /* 厂商/型号/固件/序列号 */

int n = nop_onvif_get_profiles(dev);                            /* 媒体配置数(已带RTSP地址) */
nop_onvif_profile_t p; nop_onvif_get_profile(dev, 0, &p);       /* p.token / p.stream_uri */

char snap[300];
nop_onvif_get_snapshot_uri(dev, p.token, snap, sizeof(snap));   /* 抓图URI */

nop_onvif_ptz_continuous_move(dev, p.token, -0.5f, 0.0f, 0.0f); /* 云台左移 */
nop_onvif_ptz_stop(dev, p.token, 1, 1);                         /* 停止 */

nop_onvif_device_destroy(dev);
nop_onvif_global_cleanup();
```

**依赖**：该库是 C++，故此选项需 **C++ 编译器（g++/MSVC）+ OpenSSL**；vendored 包
已自带 openssl 1.1（host/linux）。交叉编译时把 `CMakeLists.txt` 里 openssl 链接路径
指向目标平台的 openssl（或复用 v3 提到的 TUTK 自带 openssl）。默认纯 C 构建不受影响。

> 注：若本机未装 g++（只有 C 的 gcc），开启 `NOP_WITH_ONVIF` 会在 configure 阶段报
> `No CMAKE_CXX_COMPILER`。装上即可：`sudo apt-get install -y g++`。

## 7. 接入自定义传输（进阶）

协议核心零网络依赖。任何字节来源实现 `nop_transport_if`（`send`/`recv`/`ctx`）
即可：收到完整请求 JSON 后调 `nop_app_dispatch`，再把响应经 `send` 回写。
8089 HTTP server 与 TUTK P2P 隧道都是这样接入的——业务层对「命令从哪来」无感知。
参考 `src/transport/transport_mock.c`。

## 9. 设备行为服务（事件 / 推送 / 录像 / 抓图 / 联动 / SD 升级）

命令/配置外壳之外，把「配置」变成「行为」的服务层。按设备角色装配（camera 与
videoRecorder 各起所需服务），检测源由固件直接 `nop_event_publish()` 注入。

| 公共头 | 关键 API | 作用 |
|---|---|---|
| `nop_event.h` | `nop_event_hub_create` / `_subscribe` / `_publish` / `_hub_recent` | 检测事件中枢：一次发布扇出到所有订阅者；环存储供 queryEventList |
| `nop_event8012.h` | `nop_event8012_start` / `_stop` / `_publish` | camera 8012 事件中心**服务端**（NVR 登录拉取告警+JPEG） |
| `nop_event8012_client.h` | `nop_event8012_client_start` / `_stop` | videoRecorder 端 8012 **客户端**（登录所辖 camera 收事件） |
| `nop_push.h` | `nop_push_create` / `_attach_event_hub` / 设策略 | 推送引擎：静默窗口去重 + 限频（doorbellRing 豁免），发送经可插拔 fn |
| `nop_media.h` | `nop_media_create` / `_bind_hal_video` / `_subscribe` | 帧源管线：一份编码帧同时供 RTSP/P2P/录像 |
| `nop_record.h` | `nop_record_create` / `_attach_media` / `_attach_event_hub` / `_segments` | SD 录像引擎：分段滚动 + Overwrite + 事件前后录 + 分段索引 |
| `nop_nvr_recorder.h` | `nop_nvr_recorder_create` / `_add_channel` / `_remove_channel` / `_segments` | NVR 多通道录像管理器：每通道一引擎、跨盘轮转/容量感知放盘（videoRecorder 角色） |
| `nop_nvr_channels.h` | `nop_nvr_channels_create` / `_add` / `_remove` / `_list` / `_find` | NVR 通道注册表：已纳管子机表（host/口/凭据/流URI/身份），host+port 去重 |
| `nop_nvr_addcamera.h` | `nop_nvr_addcamera_start` / `_stop` / `_status` / `_offer` | AddWirelessCameras 配对窗口状态机→纳入通道注册表（已接 cap_network 命令） |
| `nop_wizard.h` | `nop_wizard_create` / `_set_password` / `_set_device_name` / `_complete` | 开机向导状态机 + Admin 密码策略（6–20 字母数字） |
| `nop_analog_camera.h` | `nop_analog_camera_create` / `_poll` / `_control` | 同轴相机即插即用：presence→绑定+改帧率，UTC(OSD)控制（需 HAL_ANALOG） |
| `nop_ptz_patrol.h` | `nop_ptz_patrol_start` / `_stop` / `_is_running` | PTZ 巡航执行引擎：后台线程循环预置位+驻留（接 operatePtzPatrol） |
| `nop_chime.h` | `nop_chime_pair_start` / `_offer` / `_list` / `_set` / `_remove` | 无线门铃注册表 + 配对窗口（接 *WirelessChime 命令） |
| `nop_snapshot.h` | `nop_snapshot_capture_to_file` | 抓图到文件（开机/插卡 → SD 根 Photograph.jpg） |
| `nop_light_linkage.h` | `nop_light_linkage_*` / `_panic` | 检测→白灯+COLOR 保持 N 秒自动熄；一键告警=灯+警笛 |
| `nop_sdcard_upgrade.h` | `nop_sdcard_upgrade_scan` | 开机扫描 SD `/upgrade/*.img` → `hal_ota.apply_sdcard_image` |
| `nop_system_events.h` | `nop_system_events_start` / `_stop` | 复位键/SD 事件：长按→保留 UID/SN 后 factory_reset；插卡→抓图+升级扫描 |
| `nop_onvif_server.h` | `nop_onvif_server_attach_event_hub` | ONVIF-events 桥：检测→ONVIF PullPoint/通知订阅者 |

典型 camera 接线（见 `nopCamera/main.c`）：建 `nop_event_hub` → 起 8012 服务端 + 推送
引擎 + 录像引擎（订阅 media+hub）+ 灯光联动；固件检测到目标即 `nop_event_publish()`，
事件自动到达 8012/推送/录像标签/ONVIF/longPolling 各路。所需 HAL 钩子（mux/OSD/抓图/
日夜/告警音/SD 升级）均可为 NULL，缺失即降级，不崩。
