# 实现：回放顺畅播放 + 主/子双轨录像

> 日期: 2026-08-11  
> 背景: 回放「有录像回显但播约 1s 就跳 / 疯狂跳帧」；根因是交织写盘 + RTP `pts` 控速 + 断点硬跳共享时钟。  
> 目标: 多路顺畅回放、空档冻结、切段/seek 后继续播；主/子分轨落盘（监控行业常见做法）。

---

## 1. 目标与非目标

### 目标

| # | 能力 |
|---|---|
| T1 | **墙钟主时钟**回放：按 `wall_time` 对齐，支持 1/2/4/8X |
| T2 | **空档冻结**：单路无数据冻最后一帧；仅当本时刻所有回放通道都空才跳下一有数据点（与已确认策略一致） |
| T3 | **切段不断播**：段 EOF → 开下一段；gap 等待墙钟，不 `pts` 硬跳 |
| T4 | **多路回放**：每通道独立 feeder + 共享 MasterClock；宫格子流 / 全屏主流 |
| T5 | **主/子分 writer**：每通道两路独立段索引，查询与实播一致 |

### 非目标（本轮不做）

- 秒级/GOP 旁路索引表（可后续加速 seek）
- 8X 只解 I 帧、倒放
- 回放音频出声
- 改盘上 64B 头布局（兼容现有格式）

---

## 2. 架构

```
录制 (streaming)
  chN pmain ──► writer_main (slot.stream=0) ──► chunk/index
  chN psub  ──► writer_sub  (slot.stream=1) ──► chunk/index
  audio     ──► writer_main (hdr.stream=2)

回放 (nvr_playback)
  GUI startTime/speed/channels/displayMode
           │
           ▼
  MasterClock(wall) = play_base_wall + elapsed*speed
           │
           ├─ feeder[i]: query(ch, stream) → play_next
           │     skip !FRAME / 错流 / audio
           │     wall > master → sleep(冻)
           │     gap → sleep 到段起点
           │     send vdec
           └─ …
```

---

## 3. 分步实现

### P1 — 回放引擎（先做，立刻消跳帧）

**文件:** `app/playback/nvr_playback.c`

| 改动 | 说明 |
|------|------|
| 忽略标记帧 | `rec_kind != RSDK_RK_FRAME` → `continue`，不送解码 |
| 墙钟控速 | 以 `MasterClock` 与 `h.wall_time` 比较：超前则 `usleep`；禁止用「pts>10s」改写全局 `play_base_*` |
| pts 仅局部 | pts 回退/大跳只重置**本 feeder** 的 fine-pace 基准，不改共享时钟 |
| gap 冻结 | `gap_out==1` 时等到 `master_wall >= frame.wall` 再送，不跳时间轴 |
| 多路 | 各 feeder 只读共享时钟；落后可快丢 P 追到 master（可选，本轮：自然追赶/按 wall 丢过旧帧到下一 I） |

**码流选择（保持产品规则）:**

- `displayMode==0` → MAIN  
- 否则 → SUB  

### P2 — 主/子双 writer

**文件:**

- `components/streaming/src/stream_internal.h` / `stream_router.c` / `stream_mgr.cpp`
- `components/recorder/src/rsdk_rec.c` / `include/rsdk_rec.h`
- `components/recorder/src/rsdk_index.c` / `include/rsdk_index.h`
- `components/recorder/src/rsdk_balance.c` / `include/rsdk_balance.h`
- `app/playback/nvr_playback.c`（按 stream 查段）

| 改动 | 说明 |
|------|------|
| writer 带 stream | `rsdk_writer` 增加 `stream`；`fill_slot` 写入 `slot.stream` |
| 开两路 | `writer_main` + `writer_sub`；`rsdk_rec_open_group(..., stream, ...)` |
| 路由 | 主帧→main，子帧→sub，音频→main |
| 事件 | `set_event`/`mark_event` 打在 **main**（查询连续轨）；sub 仅 `set_event` 打帧标签（若有） |
| 查询 | `rsdk_group_query_stream(..., stream)`；`stream<0` 表示任意（月历） |
| 回放开段 | 按 `want_stream` 查；若 SUB 无段（旧盘交织）→ fallback 查任意 + 帧级滤流 |

### P3 — 后续（文档占位，本轮不写代码）

- 每秒/每 I 的 `(wall → off)` 旁路索引，O(log n) seek  
- 段预打开（lookahead）减切段毛刺  
- 8X 只解 I

## 4. 兼容旧盘

| 数据 | slot.stream | 回放 |
|------|--------------|------|
| 旧交织段 | 0（未填） | MAIN/SUB 均可 fallback 打开 + 帧滤 `hdr.stream` |
| 新主流段 | 0 | 仅 MAIN 查询命中 |
| 新子流段 | 1 | 仅 SUB 查询命中 |

规则：`query_stream(want)` 精确匹配；若 `want==SUB` 且 0 段 → `query_stream(-1)` + 帧过滤。

---

## 5. 验收

1. 单路回放连续 ≥1 分钟无明显跳秒/跳画面（1X）。  
2. 人为停录造成 >2s 空档：画面冻结，时间轴不飞跃；有数据后继续。  
3. 多宫格 4 路子流同轴对齐，拖 seek 后各路从同一 wall 附近 I 帧起。  
4. 新录数据：`query_stream(SUB)` 只含子段；旧盘 SUB 仍能靠 fallback 播。  
5. 格式化 pause/resume、录像开关仍只影响写盘，不崩。

## 7. 风险

- 双 writer 使 chunk/索引占用约 ×2（可接受；监控常规）  
- 旧盘 fallback 在 SUB 时仍可能扫到主流段空跑：仅过渡期；新录后消失  
- 墙钟秒级粒度：同秒内用少量 pts 微调；不做亚毫秒 AV 同步（本轮无音频）
