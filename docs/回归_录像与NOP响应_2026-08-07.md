# 回归清单 — 录像 / NOP 响应 / 8K / 显示(2026-08-07)

本轮改动的问题与验证点。每条:症状 → 根因 → 修复 → **回归验证**。

---

## 1. ★ nvr_app 崩溃(录像开关关 → SIGSEGV)—— 最严重
- **症状**:GUI 关闭某通道录像开关后,nvr_app 进程消失(ps 无),8089 无响应(GUI 获取不到存储/任何接口),`dmesg` 见 `potentially unexpected fatal signal 11 ... Comm: nvr_app`。
- **根因**:**跨线程 use-after-free**。8089 命令线程执行 `nvr_stream_set_record(off)` → `stream_close_writer` → `rsdk_rec_close(c->writer)` 释放 writer;而 puller 线程正并发 `rsdk_rec_write_frame(c->writer)` 写帧 → 访问已释放对象 → 崩。
- **修复**(`stream_mgr.cpp` / `stream_router.c`):命令线程**只置 `cfg.record` 标志,绝不 close writer**。`stream_route_video` 见 `!cfg.record` 跳过写入(不 free);writer 仅在通道拆除(puller 已停)时由 `stream_router_close` 关。开关开时若无 writer 才补开(仅指针赋值,非 free,安全)。
- **回归**:①单通道反复开/关录像开关 ≥20 次,nvr_app 不崩、8089 持续响应;②开关关期间 `sda` 写扇区停增(停录)、开时恢复增长;③多通道同时开/关。

## 2. NOP 统一响应格式(全 router)
- **要求**:`statusCode` 恒 200(交互成功);**处理失败** → `200 + content:{"error":"<reason>"}`;**成功无数据** → 仅 `{"statusCode":200,"statusMsg":"OK"}`(**不带 content、不带 error**);成功有数据 → `200 + content{...}`;**不支持** → `501 + statusMsg "NOT_SUPPORT"`(唯一非 200)。
- **修复**:helper `nvr_resp_err(reason)` / `nvr_resp_ok()` / `nvr_resp_not_support()`;全 router 26 处非-200 已改。
- **回归**:①`formatStorage` 无盘 → `{"content":{"error":"no_storage"}}` statusCode=200;②坏参数 → `error:"invalid_param"`;③成功动作 → 无 content/error;④查询 → `content{数据}`;⑤真不支持命令 → 501 NOT_SUPPORT。

## 3. 持续录像排程/开关 —— NVR 本地处理(曾误透传)
- **症状**:GUI set 了 `X_NightOwl_setChannelContinuousRecordingSchedule`/`...ContinuousScheduleRecordingSwitch`,但 get 返回空;启用控制不生效。日志 `→ chN mappingonvif`(透传给了相机)。
- **根因**:这 4 个命令**不在 NVR 本地命令表** → 落到透传(发给 ONVIF 相机),NVR 未存库。
- **修复**:①本地实现 4 个 handler(存 `record_schedule` 表:sched_on + rules JSON,chn0=channel-1);②注册进 `nvr_cmd_table.c`(不再透传);③开关立即驱动 recorder(见 #1)。
- **回归**:①set 排程 → get 读回一致(不再空);②set 开关 true/false → get 一致;③日志**无** `mappingonvif`(本地处理);④开关驱动录像真启停(sda 写)。
- **未尽**:排程**时段**(rules 的 HHMMSS 区间)尚未做时间评估(当前开关=整体启停);开机未按 DB 开关初始化 `cfg.record`(重启后跟 channels.json 默认)。

## 4. RecordStatus 未上报 longPolling
- **症状**:GUI 不显示录像图标。`GUI_longPolling` 的 `RecordStatus` 硬编码 0。
- **修复**:`nvr_stream_recording_mask()`(bit chn = 该通道 `cfg.record && writer`);`cmd_GUI_longPolling` 返回真实 `RecordStatus`。
- **回归**:①录像中通道 → longPolling `RecordStatus` 对应 bit=1(bit0=通道1);②关录像 → bit=0;③GUI 显示/隐藏录像图标。
- **未尽**:`refresh:true` 全量重同步(Motion/Face 等短期状态仍 0,AI 事件未接);longPolling 目前非阻塞轮询(变化即时唤醒待 http 传输层)。

## 5. formatStorage 后免重启启用录像
- **症状**:格式化盘后录像不启(开机盘空 assemble 失败 → group=NULL → 录像禁用,格式化后不重组装)。
- **修复**:`cmd_formatStorage` 成功后 `nvr_storage_scan` + `nvr_storage_assemble` + `nvr_stream_mgr_set_group`(对录像通道补开 writer)。
- **回归**:①空盘开机(录像禁用)→ GUI 格式化 → **不重启**即开始录像(sda 写增长);②格式化失败(坏盘)→ 返回 `error:"format_failed"`。

## 6. 8K 硬解(h26xdec 模块上限)
- **根因/修复**:`vg_boot.sh` `h26xd_max_width/height` 4008→**8192**(内核模块 insmod 参数,固件级);app 层 sub-yuv 2x + `max_bs_size=2MB`/`bs_counts=4`(DIN 池 20MB)+ fail 路径关路径防 -25 级联 + 实时 IDR 起播门控。详见 [[8k-decode-insmod-gate]] 记忆。
- **回归**:①8K(7680×2160)相机单宫格出图,`dmesg` 无 `pic_w(7680) > h26xd_max_width` / `scan first header error`;②4K 通道不受影响;③切走再切回 8K,最多一个 GOP(~5s)干净起播,不永久黑/花屏。

## 9. 时区对齐(不生效根因修复 + 相机 ONVIF 授时)
- **症状**:设备时区配置不生效(排程按 UTC 评估、GUI 显示/回放时间戳错)。
- **根因**:GUI 送 `"GMT -5:00"`,旧代码 `setenv("TZ","GMT -5:00")` —— **非法 POSIX TZ 串** → tzset 失败恒 UTC;`/etc/localtime` 悬空指 `/flash/65D`;设备 glibc 2.30 无 /usr/share/zoneinfo。
- **修复**(`nvr_netime.c`/`nvr_cmd_system.c`):`GMT±H:MM`/tz_dst → 合法 POSIX(符号相反);自生成极简 TZif 写 `/flash/nvr_localtime`(持久)→ `/etc/localtime` 软链(GUI 与 nvr_app 两进程都读)→ 本进程 tzset。setTimezone 即时安装(不等 tick)+ 后台 `nvr_onvif_set_time_now` 给所有相机授时;新增本地 getTimezone。**录像帧戳保持 epoch(时区无关)不改**。
- **回归**:①setTimezone `GMT -5:00`→设备 `date` UTC-5、`GMT +8:00`→UTC+8、`tz_dst EST5EDT`→EDT(夏令 UTC-4);②`grep POSIX /tmp/nvr_app.log` 见 nvr_app 自身 localtime 翻转(排程按本地);③排程录像时段按本地时间启停;④`/etc/localtime→/flash/nvr_localtime` 开机重建(无悬空);⑤有相机时日志 `相机 ONVIF 授时: 后台下发 N 台`。
- **相机授时(用户要求)**:setTimezone 后台 `nvr_onvif_set_time_now` 遍历相机;`SetSystemDateAndTime` 已 `DateTimeType=Manual`+NVR 的 UTC(IPC 改手动、以 NVR 为主)。首次上线由 probe 已授时。

## 10. DB 持久化(重启 + OTA 都不丢)
- **症状/根因**:两库(nvr_settings.db+meta.db)在 `/tmp/nvrcfg`(tmpfs)→ 重启全失(时区/相机/排程/设备名都回默认);且旧 OTA 镜像刷 flash/sys/user 数据分区。
- **修复**:①`nvr_app.c` init 把两个 `.db` 落**持久分区 `/flash/nvrcfg`**(ubifs;mkdir,不可写才回落 config_dir);config_dir(/tmp,tmpfs)仅作只读 JSON 默认源(seed 只首启一次,'seeded' 标志护住,重启不覆盖 DB)。②OTA 镜像 `FW98633A_ota.ini` **ITEM08/09/10(flash/sys/user)=0 跳过** → OTA 保留数据分区。
- **回归**:①设 timezone+设备名 → **reboot** → 值保留(getTimezone/getName 一致、`date` 仍本地);②`ls /flash/nvrcfg` 见两库;③`/tmp/nvrcfg` 无 .db;④OTA 镜像(FW98633A.bin,71M)比 full(109M)小 ~38M(=省掉 flash+sys+user);⑤(待端到端验:真机 OTA-apply 分包部分刷,partial 是 Novatek ITEM=0 标准机制)。
- **产物**:`FW98633A.bin`=OTA(保留数据);`FW98633A_full.bin`=full(含数据,factory/救砖)。
