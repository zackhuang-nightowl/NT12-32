## 0. 一句话结论

工程**远不止骨架**：主集成链、拉流拉起、硬解上屏封装、录像引擎、8089/RTSP 服务端、NOP↔ONVIF 翻译
都是**真实现且大多有测试/编译产物佐证**。真正的问题不是"没写"，而是几处**"写了但运行期没接线"的最后一公里断点**——
它们让若干被文档标 ✅ 的功能**在真机上实际不工作**。

**能用**：连续录像、回放/检索/导出、盘管理、云存上传引擎、本地设置库读写、8089 命令路由。
**有风险/不通**：实时预览出图（HDMI 时序未配）、PoE 自动上图（密码握手空钥匙）、**远程 App 看实时画面（媒体面无帧源）**、AI 事件联动（ingest 无生产者）。

**判定：可用于联调验证，不是量产成品。** 距离"开箱即用"差 §5 的 4~5 个明确接线点。

## 3. NOP cap handler：哪些真接口、哪些假数据

- **真接 HAL 接口**（handler 里调 `hal/*` 函数指针，无则回 `NOP_ERR_NOTIMPL`）：
  cap_stream、cap_record、**cap_storage（真接盘状态：volume_count/get_volume_info/health/format）**、cap_ptz、cap_video、cap_device、cap_audio、cap_light、cap_ota、cap_system、cap_ptz_patrol。
- **纯静态 / 写死假数据（set→get 回环或返回 spec 形状空对象）**：
  **cap_cloud**（22 命令，startPlayback 返回空 url `cap_cloud.c:301`）、**cap_misc**（39 命令，getCurrentClouds 写死 `"tutk"/"pepper"`）、cap_gui_playback（getFileList 空数组、唯 `GUI_longPolling` 真）、cap_floodlight(30)、cap_push(19)、cap_network(17)、cap_gui_network/system/lan/account、cap_event、cap_doorbell、cap_agent、cap_auth。
- **混合（本地静态 + ONVIF 通道走翻译）**：cap_ai、cap_ai_advanced、cap_misc_ext。

> ⚠️ **重要前提**：nop 树内只带 **stub HAL**（`ports/stub/hal_stub.c`，channel_count 恒 1、start_stream 吐假 H.264 帧）。
> 而 **app 并未向 nop 注入真实 HAL**（`nvr_app.c` 无 `nop_media_bind_hal_video`/hal_video 注册）。
> → 即便"真接 HAL 接口"的 cap，在本固件里走的也是**桩 HAL** 或经 8089 router 被本地实现旁路。
> 三档路由实为 **native + ONVIF翻译 两档**；"透传"是编译期回退（`NOP_ONVIF_MAP` 关）+ 数据模型占位，**无运行时第三档**。

## 5. 上机前必须接的（按优先级，带证据）

**P0 — 决定核心可用性**

1. **AI 事件联动接线**：给 `nvr_evt_ingest`（`app/event/nvr_event.c:59-84`）补生产者——把 `nop_onvif_map_events_start` / 相机 AI 事件同时喂进 `a->eh`（现在只进 `nop_hub`，`nvr_app.c:339`）。否则事件录像/预览图标/推送全不触发。
2. **远程看画面的帧桥**：把 `stream_puller` 收到的编码帧转发进 `nop_media`（`nop_media_publish`）→ 喂 RTSP-to-App / TUTK；并给 `nvr_tutk_send_video`（`nvr_tutk.c:125`，当前无调用者）补调用点 + AV 鉴权回调（`nvr_tutk.c:47-48` NULL 占位）。否则 P2P/远程 RTSP 能连不能看。
3. **HDMI 输出时序/制式配置**：`mhal_vout_init` 补 `hd_videoout` 输出模式（`mhal_vout.c:55-57` TODO）。否则真机预览可能点不亮。

**P1 — 决定自动上图 / 端到端持久化**

4. **相机密码握手**：填 `nvr_crypto.c:63-66` 的 NightOwl 私有密钥常量（需 DG 提供），使 `pw_algo_ready()` 返回 1。否则加密相机无法自动接入。
5. **cap_cloud / cap_misc → 设置库**：把静态量换成真读写 nvr_settings（owner/stoken/云存开关/AV密码）。

**P2 — 外围**

6. storage SMART 明细接平台（`storage_health.c:44-55`）；OTA 烧写前校验（`nvr_ota.c:64`）；BLE 板级 GATT 链路（`nvr_app.c:207`）；OSD/抓拍（`mhal_vout.c:102` / `mhal_vdec.c:138`）。

## 6. 构建门控（易踩坑）

- 整机 `nvr_app` 仅 `NVR_WITH_ONBOARD=ON` 才链接（`app/CMakeLists.txt:64`）。
- `media_hal` 无 `BSP_ROOT` → CMake `FATAL_ERROR`（`platform/media_hal/CMakeLists.txt:19-23`），非主机可编。
- 顶层 `NVR_WITH_TUTK` 默认 OFF（`CMakeLists.txt:24`）；主机构建只出 `nvr_app_core` 静态库、不链 TUTK/hdal。
- ONVIF 客户端映射 `NOP_WITH_ONVIF` 与 ONVIF 控制服务端 `NOP_WITH_ONVIF_SERVER` **互斥**，后者所需 vendored 库本树缺失。
- openssl 头 1.1.1 vs 设备库 3.x：当前 EVP 用法兼容，真机报符号则换 openssl-3 头重编。
