# NVR 出图(视频显示)流程 —— 处理与驱动调用

> 生成:2026-08-06 · 平台:Novatek NT98633 / NA51090(aarch64,HDAL) · 范围:从 RTSP 拉流到 HDMI 出图的完整管线,含解码配置、缩放/下采样、buffer、驱动调用。
> 代码位置:`components/streaming/`(拉流+路由)、`platform/media_hal/`(解码/缩放/输出)、`app/preview/`(分屏编排)。

---

## 0. 总览拓扑

```
                       ┌───────────── 每通道 ─────────────┐
 相机 RTSP ──┬─ 主码流 NopRtspClient ─┐
             └─ 子码流 NopRtspClient ─┴─► stream_route_video()
                                              │(选 decode_stream 那一路)
                                              ▼
   硬解管线:  hd_videodec ──bind──► hd_videoproc(VPE 缩放) ──bind──► hd_videoout ──► HDMI
              (mhal_vdec_send)      (source→cell 缩放)              (分屏合成)
                                              │
                                              └─(另一路)► rsdk_rec_write_frame 录像
```

- **一句话**:RTSP 客户端拉裸帧 → 按 NAL 分类/关键帧门控 → `mhal_vdec_send` 送硬解 → 解码器→VPE→videoout 三段路径 → HDMI 分屏输出。
- **每通道一条 `dec→proc→vout` 路径**;vout 设备与分屏布局全局管理(`g_disp`,[mhal_internal.h:30](../platform/media_hal/mhal_internal.h#L30))。
- **并发**:预览线程(8089 路由)+ 各通道 RTSP rx 线程 + 主循环都碰 `g_disp`,用**递归锁** `mhal_lock/unlock` 串行化([mhal_vout.c:18-28](../platform/media_hal/mhal_vout.c#L18))。
- **批量成图**:切宫格时用 `defer_begin/end` 包住所有 open/close,**一次成图**(9 格一起出、只闪一次)。

## 2. NAL 处理与帧路由(stream_nal.c / stream_router.c)

**NAL 分类** `nal_classify`([stream_nal.c:16](../components/streaming/src/stream_nal.c#L16)):扫 Annex-B 起始码(3/4 字节),识别:
- H.264:`type&0x1F` → 7/8=SPS/PPS,5=IDR,1-4=非 IDR 片
- H.265:`(type>>1)&0x3F` → 32-34=VPS/SPS/PPS,16-23=IRAP/IDR,≤15=普通片
- 输出:`is_key`、`is_param`(纯参数集)、`has_param`、`frame_type`(I=0/P=1)

**路由** `stream_route_video`([stream_router.c:99](../components/streaming/src/stream_router.c#L99)),两条扇出:

**(a) 解码/出图**(stream_router.c:151-164):
- **仅 `decode_stream` 那一路**喂解码器(单通道一个硬解器)
- **从 IDR 起播**:Live 状态机 `WAIT_IDR/RESYNC` 等完整关键 AU(参数集+IDR)成功送入后 → `SYNCED` 连续喂;Continuity 只标记 disc,不挡录像。
- 稳态:`mhal_vdec_send(vdec, sbuf, slen, ts)`

**(b) 录像**(stream_router.c:169-185):主+子**都写**,各自 keyframe 门控(丢前置 P);写**原始帧**(非参数集拼接版),tag `f.stream`(0主/1子/2音)。

**主/子选择(核心下采样决策)**:默认 `decode_stream = NVR_STREAM_SUB`(多宫格用子码流);单画面切主码流。切换重开解码器(分辨率不同),但两路常拉,**切换即时无重连**(stream_mgr.cpp:102-114)。

## 4. 硬解(mhal_vdec.c → hd_videodec)

**路径建立**(mhal_vdec.c:193-202,dev 0,id=chn):
```
hd_videodec_open(IN(0,chn), OUT(0,chn))      → dec_path
hd_videoproc_open(IN(chn,0), OUT(chn,0))     → proc_path (VPE)
hd_videoout_open(IN(0,chn), OUT(0,0))        → vout_path  (仅上屏时)
hd_videodec_bind(dec.OUT → proc.IN)
hd_videoproc_bind(proc.OUT → vout.IN)        (仅上屏时)
```

**解码配置** `cfg_dec_path`(mhal_vdec.c:65):
- **对齐**:解码维度按 **64×64 对齐**(H264/H265 CTU 要求;否则报 "not match alignment with H.264(64x64)" 解不出帧)。如子码流 720→768。
- **上限**:单实例 8192×8192(数据手册);默认 1920×1088(维度未知时)。
- **解码内存池** `data_pool[0]`:全分辨率输出,`counts=3`;`bs_counts=8`,`max_bitrate=8Mbps`。
- **DDR 通道**(按 dts `cfg_NVR_16CH`):`DISP_DEC_IN→DDR0`、`DISP_DEC_OUT/RATIO→DDR1`;经 `vendor_common_get_ddrid` 取(mhal_vdec.c:37-47)。**放错 DDR → 解码器产不出图**。

**送帧** `mhal_vdec_send`(mhal_vdec.c:250):`hd_videodec_send_list`,Annex-B 裸帧,fourcc `VSTM`,`wait 200ms`。帧 >4MB 超比特流窗口会丢。

**抓拍/二次处理** `mhal_vdec_recv`(mhal_vdec.c:277):`hd_videodec_pull_out_buf` 拉解码后 YUV(预览走 bind 直连 vout,不需 recv)。

**reopen 防护**:切主/子码流复用同号会 `ALREADY_OPEN(-25)` → 先关后开(mhal_vdec.c:169-189);任一步失败关掉已开路径防泄漏黑屏(mhal_vdec.c:236-243)。

## 5. 缩放 / 下采样(★ 两级)

### 5.1 解码器级 sub-yuv 下采样(仅 8K,宽 > 4096)
8K 主码流(7680)超 VPE 缩放器输入上限(~4K)→ **命解码器直接吐 1/2 小图**:
- `VENDOR_VIDEODEC_PARAM_SUB_YUV_RATIO = VENDOR_SUB_RATIO_2x`(宽高都减半:**7680×2176 → 3840×1088**,≤VPE 4K 上限) — mhal_vdec.c:112-113(枚举另有 3x/4x/OFF,见 `na51090_linux_sdk/.../vendor_videodec.h`)
- 下采样输出走 `data_pool[1]` RATIO 池(DDR1),`counts=3`(环深 3) — mhal_vdec.c:101-103
- 解码输出像素格式:NV12/YUV420(HDAL 解码器默认;clearwin 填黑用 YUV422)
- videoproc 采用阈值 `SUB_RATIO_THLD={6,5}`(任何下采样即用 sub-yuv) — mhal_vdec.c:130
- **8K 比特流窗口**:`max_bs_size=2MB`,`bs_counts=4`(装下 8K IDR ~567KB;4×2MB=8MB ≤ 20.3MB 的 DIN 池) — mhal_vdec.c:92-93
- 阈值:`MHAL_SUBYUV_W_THLD = 4096`;4K 及以下**不启用**(直路更省)

### 5.2 VPE 级 source→cell 缩放(每帧上屏)
`apply_window`(mhal_vout.c:284-301)——**显示侧缩放**:
- `hd_videoproc_set(proc_path, HD_VIDEOPROC_PARAM_OUT, {rect=cell, bg=disp, pxlfmt=fb_fmt})`
- VPE 把解码源 `d->w×d->h` 缩到目标格 `w×h`(如 4K/16 宫格 cell=960×540)
- 位置/可见性:`hd_videoout_set(vout_path, HD_VIDEOOUT_PARAM_IN_WIN_ATTR, {rect, visible=1})`

> 注:**电子放大/单画面放大不是裁剪数字变焦**,而是"切 1 宫格 + 子码流升主码流"(见 §8)。真正的裁剪矩形只有悬浮块 `bind_rect`。

## 6. 出图 / 分屏(mhal_vout.c → hd_videoout)

**初始化** `mhal_vout_init`(mhal_vout.c:218):
`hd_common_init(0)` → `hd_videodec_init` → `hd_videoproc_init` → `hd_videoout_init` → 开控制路径 `hd_videoout_open(0, CTRL)` → 取 SYSCAPS/FB_FMT → 设 HDMI 模式。默认布局 16 宫格。

**HDMI 输出模式** `set_hdmi_mode`(mhal_vout.c:72),输出类型恒 HDMI:
- 3840×2160 → `HDMI_3840X2160P30`
- 1280×720 → `HDMI_1280X720P60`
- 其余/默认 → `1920×1080P60`(设失败也回落 1080p)
- `input_dim` **必须显式**(AUTO 会退到 lcd_0 720×576 → 越界、视频落模拟口)
- ⚠️ CVBS/VGA 枚举有声明但**实现只做了 HDMI**

**分屏矩形** `mhal_layout_rect`(mhal_vout.c:46):
- 方阵 1/4/9/16/25/36 → n=1/2/3/4/5/6 均分,`cell = disp/n`
- **8 宫格**特殊:1 大(左上 3×3)+ 7 小(右列 4 + 底行 3)

**绑定** `mhal_vout_bind`(win→chn,mhal_vout.c:303):越界窗口**隐藏**(`visible=0`)而非下发屏外矩形(否则 start_list 失败整屏黑)。`mhal_vout_bind_rect` 任意像素矩形(PiP,`vout_win=-2`)。

**成图** `mhal_vout_commit`(mhal_vout.c:171)——SDK `stop_module→start_module` 同款:
1. 收集所有在显通道路径
2. **先停旧集合** `hd_videodec_stop_list`→`videoproc`→`videoout`(顺序)
3. 释放 defer 期关闭的解码器
4. **再起新集合** `..._start_list`,快照到 `started_*`
- **stop 在 start 前** → 任一时刻只需 1 块 `VPD_graph_info_large`(根治 "Can't extend ms_cache_mem" / "vpd_set_graph fail -2")

**批量提交** `defer`(mhal_vout.c:153):`begin++`/`end--`,归零时一次 commit。切宫格 `set_mode` 用它包住所有 open/close。

**清黑** `mhal_vout_clear_black`(mhal_vout.c:115):`HD_VIDEOOUT_PARAM_CLEAR_WIN` 填 UYVY 中性黑 `0x00800080`(注意 `0x80008000` 会变绿)。空格稳定黑,不随视频帧闪绿。

**FB 混合**:ARGB 逐像素 alpha(关 colorkey),UI 层按像素 alpha 透出视频(mhal_vout.c:88)。⚠️ init 里**未调用**(板级 FB_ATTR get/set 可能阻塞)。

**OSD** `mhal_vout_osd`(mhal_vout.c:364):**桩/TODO**——文字在 preview 里 compose 了,但还没落到面板(应走 `hd_gfx_*`/OSG 层)。

## 7. 硬解预算门控(mhal_budget.c)

- **总量** `total = 1920×1080×360 = 746.496 Mpix/s`(数据手册硬解上限)
- **开销** `cost = w×h×fps`
- **准入** `mhal_budget_try_reserve`:超预算 → **拒绝该路预览**(录像不受影响),返回 `MHAL_VDEC_EBUDGET` → UI 显示 "超出解码能力/仅录像不预览"
- open 时预留,close 时归还;不可见通道(切页/隐藏)关解码 → 不占预算

## 8. 预览编排(app/preview/nvr_preview.c)

**唯一调用 `mhal_vout_*` 的模块**。核心驱动 `set_mode(mode, page)`(nvr_preview.c:284):
- `mode==0`:退出 LiveView,全通道 `set_display(-1)`(停解码,保留拉流+录像)
- 否则:`mhal_vout_set_layout` → 算可见集 → **先关不可见页省预算** → 按 mode 选码流(`mode==1` 主码流,否则子码流)→ `set_display(chn, win)` 开解码 → `commit`
- RTSP 会话不动,切页/切宫格**无重连**
- 6/12 宫格复用 9/16 网格只绑 N 窗

**放大/全屏**(nvr_preview.c:209-234):`fullscreen`/`single_zoom` = 切 L1 + 升主码流(**非裁剪数字变焦**,无 crop-rect)。

**悬浮块/PiP** `set_ext`(nvr_preview.c:386):千分比→像素 `pv_thousandths_to_px = clamp((v*span+500)/1000, 0, span)`,`mhal_vout_bind_rect`。

**等图** `wait_ready`(nvr_preview.c:345):轮询 `nvr_stream_display_ready` 每 20ms,超时 2000ms;任一格出图即返回,再 settle 150ms 让帧真到面板(供 LVGL "等图出了再回复")。

## 10. 编译门控 / real vs stub

- **仅目标机编**:`platform/media_hal` 只在 `NVR_WITH_ONBOARD=ON` 加入,链接预编译 `libhdal.so` + `libvendor_media.so`(aarch64,`ArmCortexA53_NT98633`);需 `-DBSP_ROOT=<na51090_linux_sdk>`,缺 `code/hdal` 直接 FATAL。
- **主机**:只能 `-fsyntax-only` 检查;`mhal_vout_*` 由 mock 替身(已随测试代码删除,见 [修改日志](修改日志.md))。
- **DDR 内存池关键值**:DIN 池(DISP_DEC_IN)约 **20.3MB**;8K 路 `bs 4×2MB=8MB` 须稳在池内。
