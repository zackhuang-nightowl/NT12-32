## 2026-08-18 · 套包 EventExtInfo：事件结束后从 NOP 相机取元数据入库

**目的**：NOP 相机打开 `AI_setEventExtInfoConfig` 后在告警期间缓存框/热区；NVR 按约定在事件录像结束后用 `AI_getEventExtInfo` 取该时段内容，写入 `meta.db`（`RSDK_DOC_AI_EVENT`）。App 四条接口走 NVR 本地库，不再透传到相机（相机会在取走后清缓存）。

**现在**：
- NOP 通道上线：异步 `AI_setEventExtInfoConfig enable=true`（间隔默认 1000ms，KV 可改）。
- 后录窗口结束：`record_sched` 回调 → 异步 `AI_getEventExtInfo`；`No entries found` 则 `BatchByReverseTime` 挑窗内一条；`Generation incomplete` / `Not enabled` 最多再试 2 次。
- LOCAL：`AI_getEventExtInfo` / `BatchByReverseTime`（支持 zlist）/ `get/setEventExtInfoConfig`。

**改动文件**：`nvr_record_sched.c/.h` · `nvr_event.c/.h` · `nvr_app.c` · `nvr_cmd_event.c` · `nvr_cmd_table.c` · `nvr_cmd_internal.h` · `app/CMakeLists.txt`

## 2026-08-17 · 多视频源按 videoSources 启用，删物理台清全部源通道

**目的**：一台设备可只开一路源，且不必是源1。`videoSources[{source,enabled}]` 是启用权威；每个启用源对应一只 NVR channel（`dev_chn` + `video_source_token`），该 channel 的拉流/ONVIF mapping/NOP 透传都打到那一路源。`GUI_LanDelDevice` 删物理台时把同 IP 的多源 channel 一起删掉。

**行为**：
- `setLanDevice`/`LanAddDevice` 带 `videoSources`：启用源有槽则钉 token，无槽则复用关掉源的槽（Add 后只开源2 → 原槽改绑源2）或另分配 LAN 槽；关掉的源删 channel。
- 无 `videoSources`：单源设备行为不变；改密写到同 IP 全部通道。
- NOP 透传 `args.channel` 改为该路 `dev_chn`，不再写死 1。

**改动文件**：`nvr_cmd_lan.c` · `nvr_cmd_router.c`

## 2026-08-17 · 34569 LocalLAN 发现 / MAC 找回

**目的**：WS-Discovery 无 MAC 或不可达时仍能扫到相机；已添加 LAN 设备 DHCP/换网段后按 MAC 找回；App 忘 NVR IP 时用同一协议搜到本机。

**协议**：UDP `:34569` 广播 20 字节 `ff…fa05`；应答头 + JSON `NetWork.NetCommon`（`HostIP` 小端 hex、`MAC`、`HttpPort`、`SN`）。

**接线**:
- 扫网：`GUI_LanSearch` = WS-Discovery 5s + 34569 1s，同 IP 合并（34569 补 MAC）

- 本机：`nvr_app` 起服听 34569，每次用 eth0 现 IP 应答（MAC/SN ← `nvr_identity`）

**改动**:`nvr_lan34569.c/.h` · `nvr_onvif/CMakeLists.txt` · `nvr_channel.c` · `nvr_cmd_lan.c` · `nvr_app.c`

### 响应示例

**WAN**（eth0 up，无 wlan）：
```json
{"value":"eth","list":["eth"],"connected":["eth"]}
```

**LAN**（eth0 1000Mbps）：
```json
{"totalPhysicalBandwidth":1000,"maxRxBandwidth":1000}
```
`allocatedRxBandwidth` 无流统计来源，**待实现**，响应不含该字段。
