# NT12-32 出图(视频上屏)实现记录 — 2026-08-05

从"拉不到流/全黑/闪屏"到"多路 PoE 相机按 LVGL 宫格正确出图"的完整根因与修复。
本轮真机迭代 nvr_app v1→v50(构建迭代,非发布号);本文是整理后的**修改记录**。

## 一、出图链路(架构)
```
PoE相机(198.18.X.1) ──RTSP──> happytime CRtspClient(每流一线程,同步跑到PLAY)
   │ on_video 裸帧(Annex-B)
   ▼
stream_router.c ──> mhal_vdec(hd_videodec) ──bind──> videoproc(VPE) ──bind──> videoout(多输入窗)
   │(旁路录像)                                                              │硬件合成
   ▼                                                                        ▼
recorder                                            VDO 视频层 + LVGL(fb1 OSD,透明格) → HDMI
```
- **LVGL = OSD 层**(fb1 ARGB,画宫格边框/通道名/占位,视频格透明);**视频 = VDO 层**(videoout 多输入窗);硬件合成到 HDMI。
- 宫格由 **LVGL 的 `GUI_setDeviceDisplayMode(displayMode)` 驱动** → nvr_app 按 displayMode 摆视频窗。

## 二、根因与修复(逐项)

### 1. VPD 合成 graph "Can't extend" 崩溃 → SDK 批量成图
- 根因:每路 RTSP 连上就单独 `hd_videoout_start`,边跑边单启会重建整屏合成 graph、旧的没释放就要新的 → 瞬时需 2 块 `VPD_graph_info_large`(reserve=1)→ 崩。
- 修:`mhal_vout_commit()`(mhal_vout.c)—— 收集所有在显通道,**先 `stop_list` 释放旧 graph,再 `start_list` 一次成图**(对齐 SDK `playback_1div_to_4div` stop/start_module)。任一刻只 1 块 large graph。mhal 加递归锁(多线程 rx/预览/主循环并发访问 g_disp)。
- 文件:`platform/media_hal/mhal_vout.c`(commit + mhal_lock/unlock)、`mhal_vdec.c`(open/close 走 commit)。

### 2. RTSP 拉流永远连不上(build_options=NULL)→ 补消息缓冲池初始化
- 根因:`rcua_build_options()` 返 NULL → OPTIONS 发不出 → 10s NODATA 反复重连。`rtsp_get_msg_buf()` 需要**两个池**:`sys_buf_init`(net_buf)+ `rtsp_msg_buf_init`(HRTSP_MSG 结构池),我们一个都没建。
- 修:`stream_puller.cpp` `puller_lib_init_once()` 首次拉流前调 `sys_buf_init(256)+rtsp_msg_buf_init(256)`(参考 happytime main.cpp)。
- 文件:`components/streaming/src/stream_puller.cpp`。

### 3. RTSP 客户端用法(对齐 media_proxy 参考)
- `rtsp_start` 是**异步**(内部起 rx 线程跑 OPTIONS→DESCRIBE→SETUP→PLAY)。原错:start 后立刻读 codec(还没回,必0)、video_cb 挂在 start 之后(丢首帧)、多调一次 rtsp_play。
- 修:**所有回调在 rtsp_start 之前挂好、不单独 play、CONNSUCC 后再开解码器**(on_notify→ensure_router_open)。
- 文件:`stream_puller.cpp`。

### 4. 自动发现停摆 → 配置通道显式 enabled=1
- 根因:配置加载的通道 `enabled=0`(一直靠 settings DB overlay 补);清了 DB 后全 DISABLED、不做 ONVIF 解析。
- 修:`fill_poe_channel`/sources 路径显式 `e->enabled=1`。
- 文件:`app/config/nvr_config.c`。

### 5. LAN 预置设备扰乱局域网/NFS → 守卫 + 清存储
- 根因:烧录 `/dvr/config/channels.json` 预置 IP 相机(192.168.9.55/60/61),开机在 eth0 主网反复探测不存在的设备,扰乱局域网(NFS 掉线)。
- 修:①nvr_config.c 加载时**跳过非 PoE 设备**(LAN 只运行期经 GUI_LanAddDevice 添加);②start.sh 清 settings DB(去持久化 LAN 通道)+ 用干净 channels.json。
- 文件:`nvr_config.c`、`~/nvrxfer/start.sh`。

### 6. 解码缓冲/对齐 → 按实际 + 64 对齐
- 4K 主码流:解码缓冲原按 1080p 分配 → `output buffer too small`。修:resolve_dim 主码流 3840×2176、子码流 1280×720。
- H264/H265 硬解要求维度 **64×64 对齐**(720 非 64 倍数 → `DST_BG_DIM not match alignment with H.264(64x64)`、解不出)。修:`mhal_vdec_open` 把 d->w/d->h **align64**(720→768)。
- 文件:`components/streaming/src/stream_router.c`(resolve_dim)、`platform/media_hal/mhal_vdec.c`(align64)。

### 7. 绿屏闪 → 杀多余 gui + 视频层清黑
- 根因A:反复部署未 reboot,旧 gui 没被 `pkill -f /tmp/gui`(实际 cmdline `./gui`)杀掉 → **累积多个 gui 争同一 framebuffer** → 闪。修:start.sh 改 `killall gui`。
- 根因B:videoout 视频层空白区从不清 → 内容不定,LVGL 绿 colorkey 抠出来跟着视频帧闪。修:`HD_VIDEOOUT_PARAM_CLEAR_WIN`(样例 liveview_with_clearwin)清成稳定黑;YUV422(UYVY)黑值 = `0x00800080`(字节 80 00 80 00;填 0x80008000 会出绿)。
- 文件:`start.sh`、`mhal_vout.c`(mhal_vout_clear_black)。

### 8. LVGL 全 NO SIGNAL 盖住视频 → longPolling 通道状态通知
- 根因:LVGL 只对 `CONN_STATE_CNN` 的格透明出图,其余画不透明 NO SIGNAL 覆盖层。gui 靠 `GUI_longPolling` 响应里的 `ChannelStatusNotify`(位图)得知通道状态变化去重拉 `getChannelStatus`。而 nopcore 的 GUI_longPolling 只返回 `{"pending"}`,没有 ChannelStatusNotify → gui 永不刷新。
- 修:app 路由(nvr_cmd_display.c)**接管 GUI_longPolling**,返回真正的 `ChannelStatusNotify`;通道 FSM 上线/掉线时置位(`nvr_chan_drain_notify`)。getChannelStatus 已正确映射 ONLINE→code 1(=CONN_STATE_CNN)。
- 文件:`app/router/nvr_cmd_display.c`、`app/channel/nvr_channel.c`。

### 9. 不同相机的数据格式 → nal 分类区分合并 AU + 参数集拼接
- 现象:相机A(SPS/PPS 独立帧 + 独立 IDR)能出;相机B(**把 SPS+PPS+I帧合在一帧发,且用 type-1 非 IDR slice 做关键帧**)全黑。
- 根因:`nal_classify` 只看第一个 NAL 是 SPS 就判 `is_param`(纯参数集),把相机B的整个合并关键帧当参数集**扣留不送解码器** → 解码器永远没关键帧。
- 修:①`nal_classify` 遍历整帧,区分 `is_param`(**纯**参数集,无 VCL)与 `has_param`(含参数集但也有 slice=合并关键帧 AU);②`stream_route_video` 只扣留纯参数集缓存,合并 AU/自带参数的关键帧直接送,只给"缺参数的独立 IDR"拼上缓存的 SPS/PPS。
- 文件:`components/streaming/src/stream_nal.{c,h}`、`stream_router.c`。

### 10. 主/子码流 + 宫格数由 LVGL 驱动
- `nvr_chan_set_stream`:单宫格→主码流、多宫格→子码流(停 puller、清 url、按新 stream 经 ONVIF 重解析)。修了 `nvr_stream_switch_stream(url=NULL)` 被 `if(!url)return` 拒绝的死 bug(改走通道层)。
- 文件:`app/channel/nvr_channel.c`、`app/preview/nvr_preview.c`(set_mode 按 displayMode 切主/子)。

### 11. 宫格位置(PoE 口→网段 +1)
- 根因:**VLAN 2001 保留给 NVR↔PoE 管理**,16 个 PoE 口走 VLAN 2002-2017,即物理口 P → VLAN 200(P+1) → 网段 (P+1)。原来按"网段=口号"判通道,导致口1相机(网段2)被判成通道2、摆错格。
- 修:`fill_poe_channel` 的 onvif_ip 网段 = **port+1**(口1→通道1→198.18.2.1→cell0;口5→通道5→198.18.6.1→cell4)。
- ⚠️ 遗留:口16→网段17,netime 目前只建 VLAN 2002-2016,**口16 需补 VLAN 2017**。
- 文件:`app/config/nvr_config.c`。

### 12. 宫格不重排 → 切布局前隐藏全部 + commit 重新成图
- 根因:①切布局时非当前视图的通道没隐藏,被绑到新布局越界(单画面 chn4→window4→y=4320 屏外、vout_set 失败);②运行期只改 IN_WIN_ATTR 在本平台不立即重排。
- 修:①`nvr_preview_set_mode` 绑新窗前**先 unbind 所有通道窗**;②切布局后 `mhal_vout_commit()`(stop_list→start_list)重新成图使新矩形生效;③`mhal_vout_set_layout` 末尾 clearwin 清残留。
- 文件:`app/preview/nvr_preview.c`、`platform/media_hal/mhal_vout.c`。
